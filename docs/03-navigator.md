> 导航负责「位置移动」：从一个符号到它的定义、它的使用者、它所在的链路，以及把「我刚才读到的位置」找回来。它是当前产品唯一做了一半的部分——链路已通，但不敢让人放心按下去。

## 1. 为什么需要它（用户视角）

读一份 AI 生成的陌生代码，人的动作序列几乎没有例外：点开一个文件，看见一个不认识的函数名，想知道它是什么、谁在调它，于是按 F12。这个动作一天要重复几百次。导航就是把这些重复动作从「人肉找」变成「一步到位」。

它为什么排第一优先？

- **因为它是最高频的动作。** 地图（看项目全貌）一天看一次，向导（带人读）一次阅读里用几回，导航一次阅读里用几百回。高频动作上的每一秒摩擦都被放大。
- **因为没有它，其它主题都落不了地。** 地图指出「热点文件在这」，用户点进去之后仍要靠导航往下走；向导给出「先看 A → 再看 B」，跳转本身仍是导航在干活；透镜解释「这是什么」，解释完的下一步永远是「去那儿看看」。导航是其它主题的执行器。
- **因为只读产品没有别的补偿手段。** 不能运行、不能打断点、不能改代码验证猜想，唯一能做的就是「走过去看」。导航弱，产品就等于一个带搜索框的查看器。
- **因为它的现状是「骗人」的。** 实测在真实项目里，按 F12 有 46% 的概率到不了位（30.9% 外部依赖 + 15.8% 未解析，见 FR-0002）。用户按下 F12 后什么都没发生，屏幕不解释、不提示、不给替代路径。工具的沉默会被读成「没这个符号」，于是用户得出错误结论。**一个不敢按时灵时不灵的导航，比没有导航更坏**——它会训练用户不再相信任何一次跳转。

导航做好了，产品的价值主张才成立：**「你不用通读，按 F12 走过去就行」**。

## 3. 关键交互形态

### 3.1 F12 按下去没反应时，用户看到什么

这是本主题最该先修的一处。今天是这样的：

```
读者按 F12
   └─> 后端返回 { locations: [], reason: 'external', symbol: 'print' }
        └─> 前端：locations 为空 → return null
             └─> Monaco 认为「没有定义」 → 什么都不发生
                  └─> 用户：是没这个符号？还是工具坏了？还是我按错了？
```

目标形态（三种结论各有各的话，且都能往下走）：

```
┌─ 编辑器右下角提示条 ────────────────────────────────────────────┐
│  ● 未跳转：print 来自外部依赖（Python 内置），本项目不索引其源码   │
│    [ 复制符号名 ]  [ 在项目里搜 print ]  [ 知道就好 ]            │
└────────────────────────────────────────────────────────────────┘

┌─ 编辑器右下角提示条 ────────────────────────────────────────────┐
│  ● 未跳转：client.fetch 的接收者 client 是局部变量，            │
│    需要类型推断才能确定类型（当前不做）                          │
│    [ 按名字搜 client.fetch ]  [ 搜 fetch ]  [ 知道就好 ]        │
└────────────────────────────────────────────────────────────────┘

┌─ 编辑器右下角提示条 ────────────────────────────────────────────┐
│  ● 这里没有可识别的符号（可能是注释、字符串或纯文本）             │
│    [ 知道就好 ]                                                 │
└────────────────────────────────────────────────────────────────┘
```

四类结论对应用户能懂的四句话：已解析（正常跳）／外部依赖（不是你的代码，所以不跳）／未解析（是代码但工具认不出类型）／此处没有符号（光标位置本身没有意义）。**核心原则：每一次没有跳转，都必须有一句人话，且至少给一个「退而求其次」的动作。**

### 3.2 常驻引用面板

Peek 浮层适合「看一眼就走」，不适合「走完所有引用」。面板形态：

```
┌─ 侧栏 · 引用：renderMarkdown ────────────────────────────────┐
│ 12 处引用 · 1 处声明 · 3 个测试文件         [ 只显示项目代码 ]│
├──────────────────────────────────────────────────────────────┤
│ ▼ src/render/markdown.ts                       (4)           │
│    ● 23:1   export function renderMarkdown(…        ← 声明   │
│      44:12  md = renderMarkdown(source, {…          ← 光标   │
│      58:7   return renderMarkdown(body)                      │
│      91:3   renderMarkdown(cached)                           │
│ ▼ src/pages/Article.tsx                        (2)           │
│      17:9   const html = renderMarkdown(raw)                 │
│      24:5   html = renderMarkdown(next)                      │
│ ▶ tests/markdown.test.ts            [测试]     (6)           │
│ ▶ src/legacy/render.ts              [未被引用?] (0)          │
├──────────────────────────────────────────────────────────────┤
│ ↑/↓ 移动 · Enter 跳过去 · Esc 回到原点 · T 只看测试          │
└──────────────────────────────────────────────────────────────┘
```

要点：按文件分组、组内按行号；**声明行单独标注**（当前 Peek 请求显式不带声明，见 §5）；测试文件单独标注并支持过滤；键盘上下 + Enter 走完全部引用后 Esc 回到出发点；每跳一次，原位置在上面留一行「← 光标」。面板常驻，用户可以边看引用边读代码，而不是浮层一失焦就没了。

### 3.3 调用层级怎么呈现

用户的问题有两句：「是谁在调它」和「它又调了谁」。两个方向不是同一个动作，但应共用同一个面板的两种模式：

```
┌─ 侧栏 · 调用层级：handleLogin ───────────  [ 调用方 | 被调用 ] ┐
│ 调用方（谁调用我）                                  深度: 2 ▾  │
│                                                              │
│ ▾ api/routes.ts:88        loginRoute()                       │
│   ▾ server.ts:31          bootstrap()                        │
│     └ cli.ts:12           main()                 [入口候选]   │
│   ▸ api/middleware.ts:44  withAuth()                         │
│ ▾ components/Login.tsx:21 onSubmit()                         │
│   └ pages/Login.tsx:9     LoginPage()            [组件]       │
│                                                              │
│ 共 4 条路径 · 2 个入口候选 · 双击任意行跳到那里               │
└──────────────────────────────────────────────────────────────┘
```

形态要点：树形而不是列表（体现「路径」而非「一堆调用点」）；每个节点可继续展开更上一层（懒加载，深度可选）；**入口候选**（`main`/`cli`/路由注册）单独标记——那是「读代码从哪开始」的答案，与 01 地图共享判定；点任意节点即跳转，跳转后历史栈仍可退回（衔接 N18）。被调用方向是同构的：树往下生长，叶子标「外部依赖 / 解析不到」。

### 3.4 位置怎么回来（历史 / 标签 / 记忆）

```
导航条：  [←] [→]        README.md > renderMarkdown > parseInline
          │   │           ▲ 面包屑可点，符号处可展开同级
          │   └ Alt+→ 前进（浏览器前进键也应等效）
          └ Alt+← 后退：回到上一个「文件+行列」

标签条：  [ markdown.ts ] [ routes.ts ● ] [ Article.tsx ]  ⋯
           ● = 这个文件里有「我标记/我改过的地方」的未读提示（书签/引用定位）

回访入口：Ctrl+P 空查询 → 「最近打开」列表（按最近访问倒序，带上次离开的行号）
          切回任一标签 → 光标与滚动位置回到上次离开处
```

判断标准只有一句话：**「我刚才在想的那一行」，都应当能在两次操作内回来**。目前只有 Alt+←/→ 这一条路径，且浏览器后退键无效，切文件必然回到第 1 行。

## 4. 与其它五个主题的关系

| 主题 | 关系 | 具体交接 |
|---|---|---|
| 01 地图 Map | 地图给「去哪」，导航负责「走过去」 | 地图的入口候选/热点文件是被点击的目标，点击后落在编辑器里；导航的调用层级（N16）反过来是地图「热点/依赖图」的数据来源之一 |
| 02 透镜 Lens | 透镜解释「这是什么」，导航负责「去那儿」 | 悬停看到签名/来源后再决定跳不跳；跳转失败时，透镜负责回答「这个 external 符号属于哪个库」，导航负责回答「所以你现在能做什么」；两者共用同一份解析结果（reason 是共同契约） |
| 04 向导 Guide | 向导给路线，导航是执行器 | 阅读路径「先看 A → 再看 B」由导航执行跳转；向导的阅读进度/「已读」标记依赖导航的位置记忆（N22）与书签（N20） |
| 05 信使 Share | 导航产出的「位置」是分享的原子 | 深链（文件+行）、复制 `path:line:col`、把引用列表贴给同事，都是导航面板的延伸动作；导航的当前状态也是回传宿主的内容 |
| 06 底座 Platform | 底座的解析精度决定导航的可信度上限 | 53% 精确命中（FR-0002）是导航现状的根本约束；索引持久化决定「上次读到哪」能否跨重启恢复；语言覆盖决定 F12 在哪几种语言里可用；搜索性能决定 N12（取消/流式）是否必需 |

一句话：**导航是唯一一个「不加新解析能力也能大幅变好」的主题**——N2/N4/N7/N11/N12/N13/N14/N18~N22/N25 全部可以用现有后端能力做出来。

## 5. 现状证据（只列事实）

以下均可直接在仓库中核对。

**端点与契约**

- 导航用的五个端点齐备：`goto-definition`（`backend/src/api/routes.ts:142`）、`find-references`（`backend/src/api/routes.ts:152`）、`document-symbols`（`backend/src/api/routes.ts:168`）、`workspace-symbols`（`backend/src/api/routes.ts:177`）、`search`（`backend/src/api/routes.ts:186`）。
- reason 契约四态：`resolved | external | unresolved | no-symbol`（`shared/types.ts:148-154`，引用结果为 `shared/types.ts:163-167`）。
- 后端确实在算 reason 并带原因返回：`backend/src/indexer/resolver.ts:266`（文件不在索引中）、`:273`（光标处无符号）、`:279`（内置符号判为 external，否则 unresolved）、`:284`（导入被解析为外部依赖）、`:293`（命中定义）；引用侧对应 `:310`、`:316`、`:319`、`:321`。
- 引用结果支持包含声明（`includeDeclaration`，`backend/src/indexer/resolver.ts:335`），结果按「文件 + 行号」排序（`backend/src/indexer/resolver.ts:363-365`），**没有「声明优先」或「测试文件」标注逻辑**。

**前端丢弃原因（N2 的直接证据）**

- 定义 Provider：拿不到结果或 `locations` 为空就 `return null`（`frontend/src/monaco-setup.ts:199`），reason 与 symbol 完全没用上。
- 引用 Provider：同样是空数组即 `return null`（`frontend/src/monaco-setup.ts:216`），且请求固定 `includeDeclaration: false`（`frontend/src/monaco-setup.ts:213`）——所以 Peek 浮层里看不到声明本身。
- 三个 Provider 的注册范围是五种语言（`frontend/src/monaco-setup.ts:187-229`），跨文件跳转由 `registerEditorOpener` 承接（`frontend/src/monaco-setup.ts:232-254`）。

**历史与位置**

- `openFileAt` 打开文件时压栈（`frontend/src/state.ts:219-224`），栈上限 300（`frontend/src/state.ts:62`）；`goBack`/`goForward` 用 `suppressHistory` 防止自激（`frontend/src/state.ts:61`、`:233-249`）。
- 深链写入用 `replaceState`（`frontend/src/state.ts:65-75`），全仓库没有 `popstate` 监听——浏览器前进/后退按钮不会回到上一个阅读位置。
- 不带行号打开文件时，定位请求固定为第 1 行第 1 列（`frontend/src/state.ts:217`）；编辑器在收到定位请求时设置选区并滚动到可见（`frontend/src/Editor.tsx:124-135`）。仓库内没有保存或恢复「光标/滚动位置」的代码；切换文件时靠 model 池复用内容（`frontend/src/Editor.tsx:79-90`，池上限 24，`frontend/src/Editor.tsx:18`）。
- `history` 只被前进后退与按钮可用性使用（`frontend/src/App.tsx:75-76`），没有任何「最近打开」列表界面。
- 编辑器为只读创建（`frontend/src/Editor.tsx:42-57`），光标位置变化会上报（`frontend/src/Editor.tsx:59-61`），面包屑据此计算（`frontend/src/App.tsx:73`）。

**面包屑与快捷键**

- 面包屑由 `symbolPathAt` 从符号树按行号推出（`frontend/src/SidePanel.tsx:91-103`），渲染在导航条内、点击即跳到符号起点（`frontend/src/App.tsx:164-180`），没有同级下拉。
- 全局快捷键在捕获阶段处理：Ctrl+P 文件、Ctrl+T 符号、Ctrl+Shift+F 搜索、Ctrl+Shift+O 大纲、Ctrl+Shift+E 文件树、Alt+←/→ 前进后退（`frontend/src/App.tsx:39-71`）。Ctrl+G 跳行与 Ctrl+F 文件内搜索由 Monaco 内置部件提供，仓库内没有自研实现。
- 半成品（Ctrl+Shift+F）是侧栏三个 tab 之一（`frontend/src/App.tsx:96-106`），搜索面板挤在侧栏 `search-host` 里（`frontend/src/App.tsx:134-148`）。

**搜索现状**

- 前端 `runSearch` 一次性 POST，拿到全部结果后按文件聚合成组（`frontend/src/state.ts:259-286`）；没有取消机制，也没有流式返回。
- 面板支持正则 / 区分大小写 / 整词 / 文件名 glob（`frontend/src/SidePanel.tsx:154-171`），选项变化会自动重跑上一次查询（`frontend/src/SidePanel.tsx:129-133`）；结果只按文件分组（`frontend/src/SidePanel.tsx:176-199`），汇总行显示命中数与截断警告（`frontend/src/SidePanel.tsx:172-175`）。
- 后端逐行正则扫描、命中上限默认 500（最大 5000），达到上限即标记 `truncated` 并停止（`backend/src/indexer/store.ts:464-514`）。契约里已经有「只在指定文件集合内搜索」的 `files` 字段（`shared/types.ts:93-102`），前端未使用。
- 没有任何搜索历史。

**工作区符号搜索（N8）**

- 后端按名字做模糊打分、按分数排序、支持 kind 过滤与条数上限（`backend/src/indexer/resolver.ts:424-452`）；前端弹层仅按名字查询、输入防抖 120ms、上下键与 Enter 选择（`frontend/src/QuickOpen.tsx:57-74`、`:109-122`），界面上没有 kind 过滤入口。

**实测数据**

- 抽样 12722 处引用：resolved 53.3% / external 30.9% / unresolved 15.8% / no-symbol 0（`FR/FR-0002-fr.md` 结果节）。
- 浏览器端回归 12/12 通过，覆盖跳定义、引用 Peek、大纲、全项目搜索、Ctrl+P、Ctrl+T 等既有能力（`FR/FR-0002-fr.md`）。

**已知限制（与导航直接相关）**

- 不做类型推断：`obj.method()` 中接收者为局部变量时无法确定类型，会返回 external 或 unresolved（`README.md` 已知限制节，解析结论说明见 `README.md:87-88`）。
- 依赖包内部不建索引，命中即标 external；`require()` 不解析；超过 1MB 的文件不进符号索引；索引为全内存结构，进程重启后重建（`README.md:126-132`）。

## 6. 边界（明确不做）

| 不做 | 理由 |
|---|---|
| 编辑、运行、调试、重构、类型检查 | 产品的差异化就在「只读」；一旦能做其中任何一件，就会被拿去和 VS Code 比，而永远比不过 |
| 自研类型推断引擎 | `obj.method()` 这类解析不了就是解析不了；要覆盖只能接现成的 LSP，属于底座主题的量级决策，不在导航里造 |
| 索引依赖包内部（node_modules / site-packages） | 边界清晰对用户更省心：外部一律标 external 并解释，而不是「跳进一坨第三方源码」 |
| 完整 git 客户端（提交/合并/分支管理） | 导航只关心「位置」，不关心版本控制；轻量 diff/历史属于向导主题 |
| 符号重命名、跨文件批量改 | 只读产品，任何写操作都不做 |
| 自研跳行/文件内搜索部件 | 编辑器自带的能力（N23/N24）直接复用，不重复造 |
| 类继承里的**方法级**重写/覆盖关系 | N15 已给「接口方法 → 实现类的方法」，这是用户真正要找的东西；再往下（谁重写了谁、虚方法分派）必须做类型推断，属底座边界 |
| 「光标/滚动位置」的跨设备同步 | 位置记忆要「读得回来」，不是「同步」；同步引入账号与上传，直接违反只读与本机承诺 |
| 为「搜索进度」做全量扫描事件 | N12 的验收信号是「能中途停止 + 结果边出边看」，已满足；百分比只对超长扫描有意义，成本（后端每文件发事件）高于收益 |
| 在提示条里展示索引版本号 | 版本号是内部实现细节，用户不关心 `revision` 是多少；用户需要的是「索引中 / 就绪」这一件事，已在状态栏 |
| 记忆式/智能的「你可能想去哪」推荐 | 属向导（04）主题；导航只回答「这里通向哪里」，不做猜测式推荐 |

## 7. 演进阶段

阶段划分对齐总纲的版本切分（V1 可信 / V2 看得全 / V4 有记忆），但只覆盖导航内的能力点。

**N-α「敢按 F12」（对应 V1 可信）**
覆盖：N2、N18、N4、N7。
要做的事：把后端已算好的四种结论翻译成用户能懂的四句话，每次不跳都给一句解释和至少一个替代动作；浏览器前进/后退键生效；引用从浮层升级为常驻面板（分组、键盘、标声明、标测试）；面包屑支持同级切换。
验收信号：在一次真实项目的通读里，「按 F12 后什么也没发生」的次数为 0；引用超过 5 处的符号，用户可以不离键盘走完全部引用；浏览器后退键与 Alt+← 行为一致。

**N-β「一次看全一条链」（对应 V2 看得全）**
覆盖：N16、N17、N15、N11、N12、N14、N25。
要做的事：调用层级双向树（先做「谁调用我」，再补「我调用了谁」）；类型层级；接口到实现的跳转；搜索升级为可摊开的独立面板并支持取消、流式、范围限定；正文里的符号名与文件路径可点击。
验收信号：能回答「这个函数从哪个入口一路调过来」和「改它会波及哪些文件」；搜索一个大仓库时能中途停止且结果边出边看；限制目录的搜索能在结果数与耗时上明显收敛。

**N-γ「读得回来」（对应 V4 有记忆）**
覆盖：N19、N20、N21、N22、N13。
要做的事：标签页与分屏对照；书签；最近打开列表；光标与滚动位置记忆；搜索历史。
验收信号：切走再切回同一文件，位置与离开时一致；关掉页面再打开，能回到上次读的文件与行（或明确告知不能）；同时对照调用方与被调用方不需要来回切。

**N-δ「顺手」（打磨）**
覆盖：N26、剩余体验细节（kind 过滤入口、提示条措辞、面板密度、键盘可达性）。
验收信号：常用组合键不冲突、不依赖鼠标；界面里出现的任何一处位置都能一键复制成 `path:line:col`。
