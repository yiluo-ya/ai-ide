# FR-0005 · 命令面板：一句话获取本项目命令，点击可跑

> 承接 `FR/FR-0001`（只读定位）→ `FR/FR-0004`（信使 Share）。本轮把右侧常驻栏的「命令」tab
> 从「只管阅读器后端自己」扩成「管本项目」。
> 一句话：**在命令面板里说一句话，让 code agent 读本项目，得出编译 / 后台启动 / 后台停止 / 测试
> 这些命令（仓库里没有的就给建议），每条点一下就能真跑，结果直接看。**

## 一、为什么做（用户视角）

现在的「命令」tab（`frontend/src/CommandPanel.tsx`）只有三件事：看阅读器后端状态、重启、停止。
这跟「我打开的这个项目怎么跑」毫无关系 —— 每换一个项目，还是得自己去翻 `package.json`、
翻 README、翻 CI 配置。

三句原话：

1. 「当配置大模型后，添加一句话获取本项目的命令」—— 面板里能说一句话，就拿到这个项目的命令。
2. 「你要调用，创建会话，用 code agent 分析代码和脚本」—— 走已有的 code agent（会读文件、会看脚本），
   不是写死一张表去猜。
3. 「自动获取：编译、后台启动、后台停止、测试命令，没有就生成。点击后可以触发真命令，命令展示好看。」

## 四、改动点（穷尽；先列全，再动手）

### 1. 类型（`shared/types.ts`，挨着 `ServiceStatus` L116-128 之后）

```ts
export type CommandKind = 'build' | 'start' | 'stop' | 'test' | 'other';
export type CommandSource = 'script' | 'generated';   // 仓库里读到的 / agent 给的建议
export type CommandRisk = 'none' | 'warn' | 'block';

export interface ProjectCommand {
  id: string;
  kind: CommandKind;
  label: string;            // 展示名，如「编译前端」
  command: string;          // 原样可执行的命令
  source: CommandSource;
  note?: string;            // 出处（package.json scripts.build）或生成理由
  background?: boolean;     // 建议以后台方式跑（start 类默认 true）
  risk?: CommandRisk;       // 后端按黑名单标注
}

export interface CommandPlan {
  projectId: string;
  createdAt: number;
  prompt: string;           // 用户那句话
  summary?: string;         // agent 的一句话结论
  model?: { provider?: string; modelId?: string } | null;
  sessionId?: string;       // 想回看分析过程时的会话 id
  commands: ProjectCommand[];
}

export interface CommandRun {
  id: string;
  projectId: string;
  command: string;
  kind: CommandKind;
  background: boolean;
  pid?: number;
  startedAt: number;
  endedAt?: number;
  exitCode?: number | null;
  status: 'running' | 'done' | 'failed' | 'stopped' | 'lost';
  logPath?: string;         // 后台运行的日志文件
  output?: string;          // 前台运行的合并输出（后台为空，去读日志）
}
```

### 2. 只读模式（这条是「不写文件」的硬约束，不能只靠提示词）

- `backend/src/agent/types.ts`：`AdapterOptions` 加 `readOnly?: boolean`（L82-90）。
- `backend/src/agent/builtin.ts`：`readOnly` 时工具集去掉 `write_file` / `edit_file`（L39-49、L77），
  并在 `systemPrompt`（L51-65）里加一句「本轮只读：不要写任何文件」。
- `backend/src/agent/sessions.ts`：`CreateSessionInput`（L29-35）加 `readOnly?`，`create` 里透传。
- `backend/src/api/agent-session.ts`：`POST /sessions`（L79-99）接受 `readOnly`（仅内部/本机用途）。

### 3. 新后端模块 `backend/src/commands.ts`

- **落盘**：`data/command-plans/<projectId>.json` 读写（参考 `services.ts:49-63` 的读写风格）。
- **`discoverCommands(projectId, prompt)`**：
  1. 建 `readOnly` 的 builtin 会话（名字 `命令分析 · <项目名>`）；
  2. `subscribe` 等 `agent_settled`（超时 180s）+ `prompt(模板 + 用户那句话)`；
  3. 取历史最后一条 assistant 文本 → 提取 ```json``` 代码块 → JSON.parse → 逐条校验
     （kind 枚举、命令非空、command 里不含换行注入）→ 用黑名单标 `risk` → 落盘；
  4. 返回 `{ plan, sessionId }`。
- **提示词模板**：先看 `package.json` / `Makefile` / `pyproject.toml` / `go.mod` / `Cargo.toml` /
  脚本目录 / README / CI 配置，再定论；每条命令必须能在项目根直接跑；仓库里有的标 `script` 并写出处，
  没有的标 `generated` 并说明理由；只输出一个 JSON 代码块。
- **执行**：
  - `runForeground`：`spawn(shell, ['-c', command])`，cwd 固定项目根，60s / 200KB 截断，
    返回 `CommandRun`（含 exitCode 与 output）。
  - `runBackground`：`spawn(..., {detached:true})`，stdout/stderr 追加到
    `data/command-logs/<runId>.log`，记 pid 进内存 Map。
  - `stopRun(runId)`：Windows `taskkill /PID <pid> /T /F`（照抄 `services.ts:129-143`），其余平台 SIGTERM。
  - `listRuns(projectId)`：正在跑的 + 最近若干条；启动时对内存里的记录探活（`isAlive` 同款）。
- **`classifyRisk(command)`**：黑名单正则 → `block` / `warn` / `none`（清单见 D4）。

### 与本文的偏差（都是你拍板或实测逼出来的）

1. **D1 改成 `~/.ide` 且整目录迁移**：不只命令清单，`projects.json` / `model-config.json` / 索引快照一起迁到用户主目录；
   旧 `<仓库根>/data` 在启动时自动复制（只复制不删，留标记）。
2. **D5 反向**：你选了「要」，所以加了自定义命令输入框（提交前先问一次危险级别，`block` 直接禁掉）。
3. **后台日志换了实现**：Windows 上两条路都实测不通 —— detached 时 `cmd` 的 `>> file` 重定向**丢输出**（0 字节），
   stdio 直给文件句柄则被 `cmd` **全缓冲**（长驻服务日志一直空）；只有「进程自己 open 文件写」可靠。
   最终由独立 worker（`bin/run-with-log.mjs`）收 pipe 自己写，实测 1 秒内可见，且 IDE 后端重启不带走它。

### 未决（要不要动，你说了算）

- **后台进程不跨 IDE 后端重启**（按 D3 实现）：重启后列表里看不到、也停不掉，但**进程本身可能还在跑**（孤儿）。
  两个可选做法：① IDE 后端启动时把上一轮遗留的 worker 一并杀掉（干净，但你起的服务会突然停）；
  ② 运行记录落盘 + 探活，重启后仍能看到并停止（多一个持久化面）。当前是 ③ 什么都不做。
