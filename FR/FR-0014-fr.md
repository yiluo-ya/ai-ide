# FR-0014 · 文件树展示被忽略的条目（灰化）+ 修改不再染色

> 用户原话（2026-10-21）：
> **「文件管理， 将ignore里的也展示，但是颜色变灰，一眼及时让人忘记的颜色 ，另外 修改里的文件不用颜色变化。」**
>
> 一句话：`.gitignore` / 内置黑名单里的东西**不再凭空消失**（看得见，但淡到不想看）；而工作区里
> 「只是改了一下」的文件**不再整行变色**（读代码时改一处就满树泛蓝太干扰）。

## 一、为什么做（用户视角）

现状（FR-0012 之后）：

- **忽略项要么整棵不见**：`ignore.ts` 判定命中的**目录**在扫描时直接剪枝（`store.ts` 的 `readDir`），
  `node_modules` / `dist` / `.git` 连一行都不出现，用户会以为「这个项目里没有这些目录」；
  命中的**文件**虽然进了 `allFiles`（2026-10-03 起 `/all-files` 会给），但**没有任何标记**，
  和正常文件一个颜色，看不出「这是被规则忽略的」。
- **改一下就整行变蓝**：2026-10-20 的 IDEA 口径里「修改 / 重命名 = 蓝」，而读代码时热重载 / 编辑器
  自动保存 / agent 写文件都会让文件常年处于 modified 状态，整棵树常年泛蓝，反而让「新增 / 冲突」
  这些真正需要一眼看到的信息被淹没。

## 二、已拍板（2026-10-21，用户答表）

| # | 问题 | 选择 | 落地含义 |
|---|---|---|---|
| 1 | 「ignore 里的」包含哪些 | **全部**：`.gitignore` / `.wcrignore` / 设置里的自定义规则 / 内置黑名单（`node_modules`、`dist`、`.venv`…） | 后端用同一个 `IgnoreMatcher` 判定，前端只认 `FileNode.ignored`，不自己推 |
| 2 | 被忽略目录点开后怎么办 | **懒加载** | 扫描时只记目录名（不下探），树上给 `lazy` 节点；展开时调 `GET /api/projects/:id/dir` 读一层 |
| 3 | 哪些 git 状态不再染色 | **修改 + 重命名都不再染色**，保留新增绿 / 删除灰 / 冲突红 | `VCS_CLASS` 里这两项映射成空类名；目录汇总（`dirVcs`）也只汇总会染色的那三档 |
| 4 | 被忽略的文件还能点开吗 | **能，和普通文件一样** | 只改样式，不动打开链路；二进制 / 超大仍由既有规则给明确提示 |

### 第二轮拍板：默认折叠成一行（2026-10-21，用户答表）

用户原话：「默认将 ignore 的直接折叠，文件和文件夹一起折叠，双击任意个灰色的文件折叠，如果只有一个灰色的文件，还是展开。」

| # | 问题 | 选择 | 落地含义 |
|---|---|---|---|
| 5 | 折叠行的名字 | **已忽略 N 项**（英文 `Ignored (N)`） | i18n key `filetree.ignoredFold`；悬停 `filetree.ignoredFoldTitle` 说明规则来源与操作 |
| 6 | 全灰层（如 `node_modules` 内部）还折吗 | **不折，直接平铺** | 只有「本层存在正常项」时才出现折叠行，否则点开只看到另一行汇总（套娃） |
| 7 | 只有 1 个灰色项时 | **不折**（文件与目录同一口径） | 为一个条目多一次点击不值；用户原话是「只有一个灰色的文件还是展开」，目录也按同口径 |
| 8 | 怎么展开 / 收起 | **折叠行单击切换 + 灰色项双击收起** | 折叠行与普通目录行同构（键盘 / 触控可达）；单击灰色文件仍是打开预览 |
| 9 | 过滤 / 只看时 | **自动展开** | 否则命中的被忽略文件被藏起来，等于搜不到 |

## 三、实现（穷尽）

### 后端

| 文件 | 改动 |
|---|---|
| `shared/types.ts` | `FileNode` 加 `ignored?: boolean`（被规则命中）与 `lazy?: boolean`（子节点还没读） |
| `backend/src/indexer/store.ts` | `ScanAcc` / `ProjectIndex` 新增 `ignoredDirs`：扫描时被整目录剪掉的目录**只记这一层**（`readDir`），索引与对账（`entries` / 快照指纹）完全不受影响；`allFiles` 的值加 `ignored` 标记（命中的文件）；`buildAllFileTree()` 把 `ignoredDirs` 也铺进树，节点带 `ignored + lazy`、**不给 `children`**；`onFileDeleted` 一并收敛子树里的 `ignoredDirs`；新增 `listDir(rel)`（读一层盘、逐项标 `ignored`（含祖先继承）+ `lazy`，目录在前）+ 私有 `ignoredUnder()` |
| `backend/src/api/routes.ts` | 新增 `GET /api/projects/:id/dir?path=`（`resolveInside` 校验，越界 400 `path_escape`）；`IntegrationManifest.endpoints` 登记 `allFiles` / `dirList` |

设计取舍：

- 忽略目录**不进** `dirs` / `entries`：`dirs` 参与 overview 的目录统计、`entries` 参与快照指纹与 P7 对账，
  一旦混进去，「忽略」这层语义就漏到索引里去了。树只需要名字，单独一个 Set 就够。
- 懒加载用**一个新的只读端点**而不是复用 `/all-files`：`/all-files` 是整棵树，按需展开时再拉整棵
  会把 `node_modules` 的十几万条目一次性拉回来；`listDir` 只 `readdir` 一层，几百条。
- `listDir` 的 `ignored` 判定**先看祖先再看自己**：`node_modules/@babel/core` 的 `@babel` 名字本身
  不在任何规则里，但它的祖先被剪枝了，它仍然是「被忽略」的。

### 前端

| 文件 | 改动 |
|---|---|
| `frontend/src/FileTree.tsx` | `VCS_CLASS` 里 `modified` / `renamed` → 空串（`vcsRowClass` 对空串不追加类名）；新增 `VCS_PAINTED`，`dirVcs` 只汇总这三档；行上按 `node.ignored` 加 `is-ignored`（文件行与目录行都加）；`lazy` 目录不显示文件计数（不知道里面几个，不报假 0）；新增 `LazyApi`（`loaded` + `request`）与 `onLoadDir` prop，`expanded` 里出现 `lazy` 目录就拉一层，拉过的用 `lazyLoaded` 缓存、`lazyBusy` 去重；子节点渲染时优先用懒加载回来的那份；`sortNodes` 加一层「被忽略沉底」（目录 → 忽略目录 → 文件 → 忽略文件） |
| `frontend/src/FileTree.tsx`（折叠） | 新增纯函数 `splitIgnored`（拆正常项 / 灰色项）与 `shouldFoldIgnored`（`normal > 0 && ignored > 1`）；一层子节点统一由新组件 `ChildRows` 渲染（正常项 → 折叠行 → 展开时的灰色项）；`TreeNode` 改收 `RowProps` 对象（`ChildRows` 与它共用一份上下文）+ `IgnoredGroups`（`open` / `auto` / `toggle` / `collapse`）；灰色行 `onDoubleClick` 收起本层组；`FileTree` 持有 `openGroups`（默认空 = 全部收着） |
| `frontend/src/filetree.css` | 删掉 `.vcs-mod` / `.vcs-ren` 两条规则；新增 `.is-ignored`：名字 / 计数 / chevron 用 `--tree-ignored` 且不加粗、热力条与徽标 `opacity: .35`、图标 `opacity: .55`；**悬停时提到 `--fg-dim`、图标 `opacity: 1`**（只改颜色不改字重，避免整行抖）；`.ignored-fold`（折叠行）同档淡色、悬停同提亮 |
| `frontend/src/styles.css` | 顶层 `:root` 新增 `--tree-ignored: color-mix(in srgb, var(--fg-dim) 70%, var(--bg))` —— 从当前主题的黯淡前景派生，**只在默认块定义一次**，9 套主题自动跟随（不用每套主题各加一条）。<br>2026-10-21 用户反馈「太淡了，完全看不到，偶尔还是要用」：从 40% 提到 **70%**，并在悬停时提亮到 `--fg-dim` |
| `frontend/src/api.ts` | 新增 `dirNodes(id, path)` |

## 验收标准

| # | 判据 |
|---|---|
| A1 | 项目根下的 `node_modules` / `dist` / `.git` 等被忽略目录**出现在文件树里**，名字明显比普通行淡，但**仍然看得清**（不能淡到发黑看不见 —— 偶尔还是要用），且不显示文件计数；悬停时提亮 |
| A1b | **默认折叠**：一层里的灰色项（文件与目录一起）收成一行「已忽略 N 项」，放在该层最末；点它展开 / 收起，**双击任一灰色项**也能收起 |
| A1c | 全灰层（如 `node_modules` 内部）与只有 1 个灰色项的层**不折**，直接平铺；过滤 / 只看时折叠组自动展开 |
| A2 | 点开被忽略目录 → 懒加载出它这一层（子目录同样淡、同样可继续点开）；不点开时**不扫描**它内部 |
| A3 | 被 `.gitignore` 命中的文件（如 `package-lock.json`）出现在树上、淡色，点开能看正文 |
| A3b | 同层排序：目录在前、文件在后，**已忽略行落在该层最末** —— 目录（正常）→ 文件（正常）→ 已忽略 N 项（展开后才是灰色项）；组内仍按名字升序 |
| A4 | 被忽略的目录 / 文件**不进入**符号索引、语言分布、阅读路线，也不进快照指纹（`/files` 树里仍看不到它们） |
| A5 | 工作区里只是「修改 / 重命名」的文件**不再变色**（行上没有 `vcs-mod` / `vcs-ren` 类，颜色与普通文件一致），新增 / 删除 / 冲突仍然染色 |
| A6 | 目录的状态色只由子树里的新增 / 删除 / 冲突决定，不会被「只有修改」的子目录带成蓝色 |
| A7 | `GET /api/projects/:id/dir?path=` 越界路径返回 400 `path_escape`；不存在的目录返回空列表不报错 |
| A8 | `npm run typecheck`、`npm test`、`npm run build` 全过；真机 headless 验收全过、无 console error |

## 五、明确不做

- 不做「被忽略目录也参与索引 / 搜索」（那是另一个产品决策，会直接把 IDE 拖慢）
- 不做「在树上临时取消某条忽略规则」的右键项（想改规则去 `.wcrignore` 或设置页）
- 不改 `gitChanges` 本身的状态集合（只是前端不再为 modified / renamed 上色；变更栏照旧显示它们）
- 不把 `--tree-ignored` 逐套主题手写一份（跟 `--fg-dim` / 背景自动派生）

### 真机踩到的四个坑

1. **`color-mix()` 的实测值是 `color(srgb 0.28 …)`**：验证脚本里把三个分量当 0~255 直接算亮度，
   得到 `ignoredLum = 0` 这种假结论；`color(srgb …)` 的分量是 0~1，脚本里按前缀换算。
2. **被忽略目录的文件计数不能沿用 `node.count`**：`countFiles()` 只数树上的子节点，`lazy` 目录没有子节点，
   会稳定显示 `0`（假的）；改成 `lazy` 时干脆不渲染计数。
3. **第二层懒加载一开始是断的**：`expanded` 的 effect 只扫 `tree` 里的 `lazy` 节点，而懒加载回来的
   子目录不在 `tree` 里 —— 点开 `node_modules/@babel` 什么都不会发生。修法是在目录行的 `onClick` 里
   先 `lazy.request(tail.path)`（已拉过 / 正在拉的自短路），effect 只负责「展开全部」这类批量场景。
   真机断言已覆盖第二层（`@babel` → 16 项）。
4. **JSX 属性位置不能写 `//` 注释**：第一版把说明写成 `// …` 夹在 `onDoubleClick` 前面，构建直接语法错；
   改用标签外的行注释。另外 `TreeNode` 改成收 `props` 对象后不需要 `const { node: _x, ...rest } = props` 这种
   「为拿剩余属性而丢弃一个变量」的写法 —— 直接显式列出传给 `ChildRows` 的字段更干净（也不会触发未使用变量）。

### 已知 / 既有

- 打开未索引文件（被忽略的 lock 文件、二进制旁路等）时 `SummaryBar` 会问 `file-summary`，后端就
  「不在符号索引内」如实 404、前端 `catch` 掉整条不渲染 —— 既有设计，不是本次回归；真机脚本把它单列为
  「已知 404」，不计入 console error。

### 未决（后续）

- 被忽略目录内**仍然禁写**（FR-0009 已定：写操作报 `ignored_path`），本轮没有改动。
- 「可索引 / 只看」筛选与新出现的忽略行如何叠加：目前筛选按 `visible` 集合走，忽略项若不在集合里照旧被滤掉
  （与「被忽略 = 看点之外」的语义一致），未额外给开关。
- 懒加载结果只在当前挂载周期内缓存（切面板 / 刷新会重拉一层）；对 `node_modules` 这种规模的目录够快，
  未做持久化缓存。
- 折叠组的展开状态目前**不跨挂载持久化**（收起 = 默认），与 FR-0012 的目录展开状态不同口径；
  如果用户希望「我展开过的灰色组一直展开」，再接入 `treeState`。
