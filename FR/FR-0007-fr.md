# FR-0007 · pi 后端的「安装 / 定位」机制

> 承接 `FR/FR-0005`（命令面板，会话后端选择）。本轮解决一个交付问题：
> **源码给出去时不含 pi，别人拿到后怎么把 pi 接上。**
> 一句话：**给 pi 一个显式的定位链（设置里的路径 → `~/.ide/agents/pi/` → PATH），
> 找不到时给出可执行的安装指引；OpenHands 只留位置。**

## 一、为什么做（用户视角）

用户原话：「我的源码给出去后，是不包含 pi 和 openhands 的，那么我肯定要去安装这个东西，
那就要通过命令或者前端按钮导入，或者将 pi 放到指定位置才能安装。」

现状问题：`pi.ts:131-144` 写死调用 PATH 上的 `pi`（Windows `cmd /c pi ...`），
**没有任何配置项、没有落点**。用户机器上装上 Node 却没全局装 pi 时，界面给的是一句 spawn 失败，
既没说「去哪装」也没说「放哪能被认出来」。openhands 更彻底：`adapter.ts:23` 直接抛未实现。

本机实测（2026-10-03）：pi 已全局装（0.87.1，`C:\Users\chenfg\AppData\Roaming\npm`），
所以开发者本人感觉不到这个问题 —— 换台机器就暴露。

### 与本文的偏差

1. §四 漏列两处，实施时补上：`shared/types.ts`（`AgentRuntimeStatus`）与 `frontend/src/styles.css`（三条样式）。
2. 响应体多一个 `pi.resolved`（该候选是否指向真实存在的文件）：前端不显示，但它区分「真找不到」与「装了但探测失败」，`pi.ts` 的报错替换也靠它。
3. Windows 命令行拼法比 §四 写的多一层：整行再加一层引号 + `windowsVerbatimArguments`。Node 24 会自己去转义参数，直接把 `"路径" args` 交给 cmd 会被当成字面量；实测 7 种写法里只有「三引号 + verbatim」既认带空格的路径、也认裸名。
4. 包名与命令按本机实测落定（§四 未写死）：包 `@earendil-works/pi-coding-agent`，两条装法（`-g` 进 PATH / `--prefix` 进落点）。
5. 指引里的安装命令**不带版本号**，所以装到的是当时的最新版（本机实测：原来的 0.87.1 → 1.0.1）。这是有意为之（同事拿到的就是最新版），但提醒：pi 从 0.x 到 1.0 是跨大版本，行为差异要自己验；老环境要锁版本就在命令后加 `@0.87.1`。
6. 「没装」时不再拼系统原话（上一条实测发现）：Windows 下 cmd 的报错是 GBK，按 utf8 读是乱码，拼在指引后面只会让人以为是工具坏了。

### 未决项

- 探测失败 ≠ 不可用（D6）：设置页如实显示状态，**不**据此禁用「新建会话」的下拉。要改得先能区分「没装 / 装了报错 / 探测超时」。
- 落点的 `openhands/` 只留目录，适配器仍未实现（§六）。
- 手填路径不做额外解析（Windows 快捷方式、`nvm` 切换后失效的路径）—— 需要时下一轮再说。
