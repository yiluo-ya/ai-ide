# FR-0006 · Code Agent 会话内容的 md / html 展示

> 承接 `FR/FR-0005`（命令面板）。本轮把中间的 Code Agent 会话从「纯文本 + 折叠」升级成
> **能看懂格式的会话记录**：
> 一句话：**助手正文与工具结果按 Markdown 渲染，```html 块与 HTML 文档用沙箱 iframe 预览，
> 代码块能复制，整条会话能导出成 .md / .html。**

## 一、为什么做（用户视角）

用户原话：「对于 code agent 的会话内容，支持 md 格式和 html 格式的展示。」

现状是 `AgentView.tsx` 把 `block.text` 直接塞进 `<div className="ag-text">`（`white-space: pre-wrap`），
工具结果是 `<pre>` 原文。于是 agent 精心写的标题 / 列表 / 表格 / 代码围栏全成了难读的符号，
它给出的 HTML 片段也只能看源码。

## 二、已拍板（2026-10-03，用户答表）

| # | 问题 | 选择 | 落地含义 |

## 三、默认（我的判断，不同意就直说）

| # | 未拍板项 | 默认做法 |
|---|---|---|
| D1 | 工具结果全部当 Markdown 吗 | **不**。日志 / 文件内容 / JSON 原样最忠实，只在带明确 Markdown 结构（围栏 / 标题 / 表格 / 任务列表 / 引用 / 粗体 / 链接）或 HTML 文档特征时才渲染，并给「源码」切回去（`looksRichText`） |
| D2 | 什么样的 HTML 进 iframe | 只有「像一份文档 / 带样式的片段」（`<!doctype` / `<html` / `<body` / `<style` / `<script`，`isHtmlDocument`）才隔离；`<table>`、`<details>` 这类零散标签仍走**清洗后内联**渲染 |
| D3 | iframe 的 sandbox 取值 | `sandbox="allow-same-origin"`（**不给 `allow-scripts`**）：脚本不执行、表单不提交、不能导航顶层；留 `allow-same-origin` 只为按内容读高度做自适应 |
| D4 | 干净程度 | 正文里的链接一律 `target="_blank" rel="noopener noreferrer"`（点了不清空 IDE）；清洗额外挡掉 `style` 属性与 `<style>` 块（可用来盖住整页做钓鱼） |
| D5 | 导出的 html 里 HTML 块怎么画 | 不用 iframe（导出文件要自洽），用同一套清洗后内联渲染 |
| D6 | 代码高亮 | **不做**（不引 highlight.js）：语言标签 + 等宽 + 复制按钮，需要高亮时导出到编辑器看 |

## 六、结果（2026-10-03 落地）

- **真浏览器实测**（临时页面 + Playwright/Chromium，验证后已删）：
  `h1`=会话渲染样例、粗体 / 行内代码 / 表格 / `target=_blank`+`rel` 都在；2 个代码卡（`ts` / `HTML`）；

  裸 `<div>` 走内联渲染（没进 iframe）；点复制按钮后按钮显示「已复制」、剪贴板内容为 `const answer = 42;`；
  预览 ⇄ 源码切换可用；iframe 高度自适应到 121px；`window.__xss` 全程为 null（`<script>` 与 `onerror` 都被清掉）。
  唯一的 404 来自样例里故意写的 `<img src="x">`（img 保留、onerror 去掉），不是实现问题。

### 与本文的偏差

1. **D2 细化**：`<script>` 也算「文档特征」（避免脚本片段被内联渲染路径碰到），所以含脚本的片段统一进 iframe。
2. **工具结果默认渲染**范围按 D1 收紧了 —— 用户选的是「工具结果也走 md 渲染」，但纯日志按 md 渲染会失真，
   改成「检测到结构才渲染 + 一键切源码」。

### 更新（2026-10-03 晚）：会话区字号跟随设置里的「字号」

用户追加要求：「设置里的字体变化时，code agent 和会话里的字体也可以跟随变化。或者单独设置字体也行。」
选**跟随**（不加新设置项）。

**根因**：设置里的「字号」只写 `--ui-font-size`（`prefs.ts` 的 `applyPrefs`），而字号阶
`--fs-xs..xl` 在 `styles.css:12-16` 是**固定 px**；agent 区一律用 `var(--fs-*)`，
所以会话区被钉死在 13px / 12px，滑字号时纹丝不动。

| 位置 | 做了什么 |
|---|---|
| `frontend/src/agent.css` | `.ag-side, .agent-view` 作用域内按同一比例（基准 13px：−2 / −1 / 0 / +2 / +4）用 `calc(var(--ui-font-size))` 重算字号阶 —— 默认 13px 时算出来与全局字阶完全一致，**视觉不变**，只有调字号才整体缩放 |
| `frontend/src/markdown.ts` | `htmlPreviewDoc(html, fontSize = 14)`：iframe 是独立文档、拿不到父页 CSS 变量，基础字号改由调用方传（原 14px 常量改为函数） |
| `frontend/src/RichText.tsx` | `HtmlBlock` 用 `usePrefs().fontSize` 生成预览文档 —— HTML 预览也跟着字号变 |
| `tests/ui/platform.mjs` | 新增用例 **AG-FONT**：在 P24 已设 16px 的前提下，断言会话区正文 = 16px、小字 = 15px（修复前是 13px / 12px） |

**验证**：`test:ui` 底座套件 **9/9 通过**（含新增 AG-FONT：`会话区 16px / 15px、内容区 15px`）；
`tsc --noEmit`、`vitest`（56 例）、`build` 均通过。

**边界（有意为之）**：作用域只到 agent 区 —— 设置面板自身的「模型」区块（`.ms-*`）与其它面板仍在
全局固定字阶上；全站另有 61 处硬编码 px 字号，本轮不动（用户只提了 code agent 与会话）。

### 未决（要不要动，你说了算）

- **代码高亮**：当前只用等宽字体。要语法着色需引 highlight.js（或复用 Monaco 的 tokenizer），会明显变重。
- **导出范围**：现在导出的是「当前已加载的消息」（含正在流式生成的那条），不含未加载的历史分页（目前也没有分页）。
- **HTML 预览的交互**：sandbox 不给 `allow-scripts`，所以 agent 写的交互式 HTML（图表 / 按钮）预览里是静态的 —— 这是安全取舍。
