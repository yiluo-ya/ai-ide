好，有后端这就把最大的限制解除了。**索引引擎跑后端，前端只做渲染和查询**，这是最舒服的架构——性能、规模、精度都不再是瓶颈。我重新给一版设计。

**核心思路**：
- 后端跑索引，前端只发查询、渲染结果
- Agent 和「代码导航」共享同一个索引服务
- 前端用 Monaco 的 Provider 接口，自动获得 F12 / Shift+F12 / 大纲

## 二、后端设计

### 2.1 索引服务（核心）

复用前面设计文档里的所有内容（tree-sitter、作用域链、只分析当前项目），这里只讲**怎么把它包成服务**。

**技术选型建议**：

| 你的后端语言 | 推荐方案 | 理由 |
|-------------|---------|------|
| Node.js | `tree-sitter` (node 绑定) + `web-tree-sitter` | 和前端共用一套 query，开发最快 |
| Python | `tree-sitter` (py 绑定) | 直接可用，性能够 |
| Go | `go-tree-sitter` | 绑定成熟 |
| Rust | `tree-sitter` crate | 性能最好，但开发慢 |

**如果后端是 Node**，我强烈建议用 Node 绑定，因为：
1. 和前端共享 TypeScript 类型定义
2. query 语句可以前后端复用
3. 不用跨语言通信

### 2.2 服务接口

```typescript
// 内部服务接口（不是 HTTP，是后端模块间调用）
interface CodeIntelligenceService {
  // 生命周期
  init(projectRoot: string): Promise<void>;
  shutdown(): Promise<void>;

  // 查询
  gotoDefinition(file: string, line: number, col: number): Promise<Location[]>;
  findReferences(file: string, line: number, col: number, includeDecl: boolean): Promise<Location[]>;
  documentSymbols(file: string): Promise<SymbolInfo[]>;
  workspaceSymbols(query: string): Promise<SymbolInfo[]>;
  hover(file: string, line: number, col: number): Promise<HoverInfo | null>;

  // 搜索
  searchText(query: string, options: SearchOptions): Promise<Match[]>;

  // 更新
  onFileChanged(file: string): Promise<void>;
  onFileCreated(file: string): Promise<void>;
  onFileDeleted(file: string): Promise<void>;
}

interface Location {
  file: string;       // 相对项目根的路径
  range: { start: { line: number; col: number }; end: { line: number; col: number } };
}

interface SymbolInfo {
  name: string;
  kind: 'function' | 'class' | 'variable' | 'method' | 'import' | ...;
  location: Location;
  containerName?: string;  // 所属类/模块
}
```

### 2.3 HTTP API（暴露给前端）

```typescript
// 用 Express/Fastify/Hono 包一层
POST /api/code/goto-definition
  body: { file, line, col }
  → { locations: Location[] }

POST /api/code/find-references
  body: { file, line, col, includeDecl? }
  → { locations: Location[] }

GET  /api/code/document-symbols?file=src/foo.py
  → { symbols: SymbolInfo[] }

GET  /api/code/workspace-symbols?q=handle
  → { symbols: SymbolInfo[] }

POST /api/code/search
  body: { query, options }
  → { matches: Match[] }

GET  /api/code/status
  → { indexing: boolean, filesIndexed: number, progress: number }
```

**注意**：位置统一用 `{ line, col }`（1-based 或 0-based 要前后端约定好），**不要用字节偏移**，因为前端 Monaco 用的是行列坐标。

### 2.4 文件监听与增量更新

Agent 会改文件，索引必须跟着更新。三种触发方式：

**方式一：文件系统监听（推荐）**
```typescript
import chokidar from 'chokidar';

const watcher = chokidar.watch(projectRoot, {
  ignored: /(node_modules|\.git|__pycache__|\.venv|venv|target|dist|build)/,
  ignoreInitial: true,
  awaitWriteFinish: { stabilityThreshold: 300 },  // 防抖
});

watcher.on('change', (path) => index.onFileChanged(path));
watcher.on('add', (path) => index.onFileCreated(path));
watcher.on('unlink', (path) => index.onFileDeleted(path));
```

**方式二：Agent 主动通知**
Agent 写文件后主动调 `index.onFileChanged(path)`，比监听更可靠（尤其容器/远程文件系统）。

**方式三：混合**
监听 + Agent 通知，双保险。

**增量更新的粒度**：
- 单文件变更 → 重解析该文件，更新索引
- 大量文件变更（如 git checkout）→ 批量更新 + 防抖
- 全量重建 → 提供手动触发接口

### 2.5 Agent 工具集成

这是最有价值的部分。把索引暴露成 agent 的 function calling 工具：

```typescript
const codeIntelligenceTools = [
  {
    name: 'goto_definition',
    description: '跳转到某个符号的定义位置。当用户问"这个函数在哪定义"时使用。',
    parameters: {
      type: 'object',
      properties: {
        file: { type: 'string', description: '文件路径（相对项目根）' },
        line: { type: 'number', description: '行号（1-based）' },
        col: { type: 'number', description: '列号（1-based）' },
      },
      required: ['file', 'line', 'col'],
    },
    execute: async (args) => service.gotoDefinition(args.file, args.line, args.col),
  },
  {
    name: 'find_references',
    description: '查找某个符号在项目中的所有引用。当用户问"这个函数被哪些地方调用"、或者判断某段代码能否删除时使用。',
    parameters: { /* ... */ },
    execute: async (args) => service.findReferences(args.file, args.line, args.col, false),
  },
  {
    name: 'search_symbols',
    description: '按名字搜索项目中的符号（函数、类、变量等）。当用户说"找到所有处理用户的函数"时使用。',
    parameters: {
      type: 'object',
      properties: {
        query: { type: 'string', description: '符号名或部分名' },
        kind: { type: 'string', enum: ['function', 'class', 'variable', 'any'] },
      },
    },
    execute: async (args) => service.workspaceSymbols(args.query),
  },
  {
    name: 'search_text',
    description: '在项目中进行文本搜索。当用户要找字符串、注释或不确定是符号的内容时使用。',
    parameters: {
      type: 'object',
      properties: {
        query: { type: 'string' },
        filePattern: { type: 'string', description: '如 *.py，可选' },
      },
    },
    execute: async (args) => service.searchText(args.query, args),
  },
];
```

**这一步让 agent 从「猜代码」变成「查代码」**。比如用户问「这个 `handle_user` 函数能删吗？」，agent 会：
1. 调 `find_references` 查引用
2. 返回「有 3 处引用，分别在 api.py:15, api.py:42, test_api.py:8」
3. 判断「有测试引用，建议保留」

## 三、前端设计

### 3.1 编辑器选型

**Monaco 是首选**，因为：
- VS Code 同款，用户熟悉
- 内置 DefinitionProvider / ReferenceProvider / DocumentSymbolProvider 接口
- 你只需要注册 Provider，F12 / Shift+F12 / 右键菜单自动生效

```typescript
import * as monaco from 'monaco-editor';

// 注册跳转定义
monaco.languages.registerDefinitionProvider('python', {
  async provideDefinition(model, position) {
    const res = await fetch('/api/code/goto-definition', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        file: model.uri.path,
        line: position.lineNumber,
        col: position.column,
      }),
    });
    const { locations } = await res.json();
    return locations.map(loc => ({
      uri: monaco.Uri.file(loc.file),
      range: new monaco.Range(
        loc.range.start.line, loc.range.start.col,
        loc.range.end.line, loc.range.end.col
      ),
    }));
  },
});

// 注册查找引用
monaco.languages.registerReferenceProvider('python', {
  async provideReferences(model, position) {
    const res = await fetch('/api/code/find-references', { /* ... */ });
    const { locations } = await res.json();
    return locations.map(loc => ({
      uri: monaco.Uri.file(loc.file),
      range: new monaco.Range(/* ... */),
    }));
  },
});

// 注册文件大纲
monaco.languages.registerDocumentSymbolProvider('python', {
  async provideDocumentSymbols(model) {
    const res = await fetch(`/api/code/document-symbols?file=${model.uri.path}`);
    const { symbols } = await res.json();
    return symbols.map(toMonacoSymbol);
  },
});
```

**注册完这三个 Provider，用户就能用 F12、Shift+F12、Ctrl+Shift+O，和 VS Code 体验一致。**

## 四、完整请求流程示例

### 场景一：用户点 F12 跳定义

```
1. 用户在编辑器里把光标放在 `handle_user` 上，按 F12
2. Monaco 调用 DefinitionProvider
3. 前端 POST /api/code/goto-definition { file, line, col }
4. 后端：
   a. 从索引拿到该文件的 AST
   b. 在光标位置找到标识符节点
   c. 沿作用域链解析，找到定义
   d. 返回 { locations: [{ file: 'src/service.py', range: {...} }] }
5. 前端 Monaco 收到结果，自动打开 src/service.py 并跳转
```

### 场景二：用户问 agent「这个函数能删吗」

```
1. 用户: "handle_user 这个函数能删吗？"
2. Agent 调 find_references({ file: 'src/service.py', line: 42, col: 5 })
3. 后端返回 3 个引用位置
4. Agent 判断: "有 3 处引用：api.py:15（生产代码）、api.py:42（生产代码）、
   test_api.py:8（测试）。生产代码有引用，不建议删除。"
5. 前端渲染消息，把 3 个位置渲染成可点击链接
6. 用户点击 api.py:15，编辑器跳转到那行
```

### 场景三：用户搜索「所有处理用户的函数」

```
1. 用户: "找到所有处理用户的函数"
2. Agent 调 workspace_symbols({ query: 'user', kind: 'function' })
3. 后端从符号索引里返回匹配的符号
4. Agent 整理后返回: "找到 5 个相关函数..."
5. 前端展示列表，点击跳转
```

## 五、性能与规模

后端跑索引，规模不再是问题：

| 项目规模 | 索引时间 | 内存 | 查询延迟 |
|---------|---------|------|---------|
| < 1000 文件 | < 3 秒 | < 200 MB | < 20 ms |
| 1000 ~ 10000 文件 | 3~30 秒 | 200 MB ~ 1 GB | < 50 ms |
| 10000 ~ 100000 文件 | 30 秒 ~ 5 分钟 | 1 ~ 5 GB | < 100 ms |

**优化手段**：
1. **并行解析**：多线程/多进程，按文件并行
2. **惰性绑定**：索引时只提取定义/引用，绑定在首次查询时做
3. **持久化**：SQLite 存索引，冷启动只加载变化的文件
4. **分片**：超大项目按目录分片，按需加载
5. **缓存**：热点查询结果缓存

**冷启动优化**：如果项目大，首次索引慢，可以：
- 后台异步索引，前端先可用（部分功能）
- 持久化索引，下次启动秒开
- 只索引用户打开的文件 + 按需扩展

## 八、关键设计决策

1. **索引在后端，前端只查询**——性能、规模、精度都不再受限
2. **用 Monaco 的 Provider 接口**——F12/Shift+F12/大纲自动生效，不用自己写 UI
3. **位置用行列坐标**——前后端统一，避免字节偏移的编码问题
4. **Agent 和导航共享索引**——一份索引，两种消费方式
5. **文件监听 + Agent 通知双保险**——保证索引和实际文件同步
6. **Agent 工具化**——让 agent 从「猜代码」变成「查代码」，这是最大价值

---

## 九、几个坑

1. **前后端行列坐标要约定一致**：0-based 还是 1-based，UTF-16 还是 UTF-8，必须统一
2. **Monaco 的 model 管理**：多文件时注意 dispose，否则内存泄漏
3. **文件监听的防抖**：agent 批量改文件时会触发大量事件，要防抖
4. **索引和文件的最终一致性**：监听可能丢事件，定期全量校验
5. **大文件保护**：超过阈值的文件跳过或降级为文本搜索
6. **权限和路径安全**：API 要校验文件路径在项目根内，防止路径穿越

---

## 十、最关键的判断

你的场景（有后端 + 网页前端 + agent）是**做代码导航工具的最理想形态**：

- 性能不受限（后端跑）
- 用户体验好（Monaco 原生）
- 和 agent 深度联动（共享索引）
- 规模可扩展（持久化、分片）

**优先做这三件事**：
1. 后端 `goto_definition` + 前端 Monaco DefinitionProvider（1 周内可演示）
2. 后端 `find_references` + Agent 工具化（让 agent 能查引用）
3. Agent 消息里的符号可点击（体验提升最大）
