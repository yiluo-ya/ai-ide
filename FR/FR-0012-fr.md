# FR-0012 · 文件树导航（收拢全部 / 定位当前文件 / 面包屑 …）

> 用户原话：「在文件管理上添加一个收拢所有文件，定位到打开文件的位置 的能力。你看看 vscode，看看还有其他能能力不，补上」
> 一句话：读代码时「这个文件在树的哪儿」「树太乱我想一趟收起来」两个高频动作，加上 VS Code 文件资源管理器里还差的那几件顺手事。

## 一、为什么做（用户视角）

现状（FR-0009 之后）：文件树有新建 / 重命名 / 移动 / 复制 / 删除 / 在旁边打开 / 在终端中运行 / 复制路径 / 文件名过滤，但

- 展开态只存在 `FileTree` 组件内（`useState`），**没有收拢入口**，也没有持久化 —— 在大项目里展开十几层后只能一个个点回去；
- **找不到当前打开的文件在哪**：`activeFile` 只用来加 `.active` 样式，没有「展开祖先链 + 滚到它」的能力，标签页也没有「在树中定位」。

按 VS Code 文件资源管理器的能力做了一轮对照盘点（10 项），由用户勾选本轮范围。

## 三、默认（我的判断，不同意就直说）

| # | 未拍板项 | 默认做法 |
|---|---|---|
| D1 | 快捷键键位 | **定位 = `Alt+F`**（VS Code / IDEA 两套一致，`F` = file）；**收拢** = VS Code `Ctrl+Shift+-` / IDEA `Ctrl+Alt+-` |
| D2 | 定位时被过滤挡住 | 工具按钮 / `Alt+F` / 标签右键这三条**手动**路径先清空文件名过滤（过滤态下树里根本没有它）；「只看孤立 / 最近改动」不动，被它们挡住就静默（那是用户特意开的视图） |
| D3 | autoReveal 默认 | **开**；设置 → 界面 → 「打开文件时自动在文件树中定位」可关 |
| D4 | 定位的视觉反馈 | 展开整条祖先链 → `scrollIntoView({ block: 'nearest' })` → 该行闪烁 1.2 s（动效减弱时由全局规则关掉动画） |
| D5 | 状态持久化 | 按项目分键 `wcr:tree:<projectId>`（与 `wcr:positions:*` 同规格）；切项目用 `FileTree` 的 `key` 重挂载，避免把 A 的展开态写进 B |
| D6 | 「只显示可索引文件」 | 视图开关（不持久化），隐藏 `indexed === false` 的文件（二进制 / 被 `.wcrignore`-`.gitignore` 忽略的）；目录靠子树存活 |
| D7 | 面包屑交互 | 段 = 项目名 › 目录… › 文件名；点任一段下拉该目录子项，点目录下钻、点文件打开；不做键盘导航，也不做 VS Code 面包屑末尾的「符号段」 |
| D8 | 面包屑位置 | 编辑器顶栏下方一行；只在代码视图显示（项目地图 / Agent 视图不显示） |
| D9 | 复制相对路径 | 与现有「复制路径」（绝对路径）并列；只对节点出现，项目根不出现 |

## 六、明确不做

- 树键盘导航（↑↓ 选择 / ←→ 折叠展开 / Enter 打开 / Home / End）
- 拖拽文件到编辑器区域打开（FR-0009 的遗留）
- 排序方式切换（名称 / 修改时间 / 大小）
- 「在系统文件管理器中显示」（浏览器端做不到）
- 面包屑的键盘导航与「符号段」
- 多选批量操作、把树状态同步到服务端

## 七、结果（2026-10-14 实施）

### 落地

与 §四 一致，无遗漏；实施时补了两处细节：

- `FileTree` 靠 `key={projectId}` 重挂载来隔离项目间的树状态 —— 比在同一实例里监听 `projectId` 变化可靠（写回 effect 与重载 effect 在同一轮里跑会串项目）。
- autoReveal 用模块级的 `lastAutoRevealed`（`projectId|file`）记住「已跟随过的文件」—— 否则切面板重挂载会再展开一次，与「收拢 / 状态持久化」自相矛盾（autoReveal 的语义是「打开文件时跟随」，不是「面板每次出现都展开」）。
- 定位选择器用「attribute + 只转义引号 / 反斜杠」而不是 `CSS.escape`（属性选择器里其余字符本就不用转义，且少一个环境依赖）。

### 真机踩到的两个坑（都写进了脚本注释）

1. **「收拢所有文件夹」不收根目录下的文件行** —— 第一版脚本断言「文件行 = 0」直接失败（夹具根下有 4 个文件）。这不是缺陷：VS Code 的 Collapse Folders 也只收目录。判据改成「没有展开的目录行」。
2. **默认 keymap 是 IDEA，`Ctrl+P` 不打开文件**（IDEA 方案里是 `Ctrl+Shift+N`）—— 脚本原先用 `Ctrl+P` 走快速打开，`quickopen-input` 一直等不到。脚本改成走树点击 / 面包屑打开文件，反而更贴近真实操作。

### 与本文的偏差

- §四 的 `frontend/src/prefs.test.ts` 那条「合法值生效」用例是全字段 `toEqual`，新增 `autoReveal` 后必须补上断言（已补）。
- 未动 `tests/ui/navigator.mjs`：它的 `setup` 依赖 `panel.mjs` 里已过时的 `#wcr-tab-files`（VS Code 布局迁移后是 `#wcr-activity-left-files`），属既存基线失败，在它上面加用例只会跟着一起不跑；真机验收改走 `tmp/fr0012-ui.mjs`（与 FR-0009 / FR-0011 的做法一致）。
