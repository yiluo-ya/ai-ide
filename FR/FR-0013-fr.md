# FR-0013 · pi 安装入口 / 会话落盘与续传 / 模型配置同步到 pi

> 用户原话（2026-10-15，三条连着给）：
> **3、** 新建会话时，如果 pi 不存在时，在「知道了」前加一个「在终端安装」，将 npm 自动填写到终端上。然后安装。
> **4、** 会话记录没有保留，应该跟随项目，可以在 .ide 下面创建一个路径来保存会话记录。做到续传的能力。
> **5、** 需要同步模型配置，包括安装 pi 后的第一次，以后怎么办。
>
> 一句话：把 pi 这条链路的三处断点接上 —— **装之前**（点一下就进终端）、**重启之后**（会话还在、还能接着聊）、**配完之后**（本项目「模型」里配的东西 pi 也能用）。

## 一、为什么做（用户视角）

现状（FR-0007 / Code Agent 落地之后）：

- **装 pi 太绕**：新建 pi 会话失败时只弹一条错误横幅（`AgentView.tsx:238` 的 `.ag-banner`），文案里给了两条 npm 命令，但用户得自己复制、自己开终端、自己粘。要的是「点一下 → 终端里已经躺好命令」。
- **会话重启即清**：`backend/src/agent/sessions.ts:4` 明确写着「刻意不做持久化」——`Map` 一清，左栏空掉；pi 侧还额外用了 `--no-session`（`pi.ts:138`），连 pi 自己的会话文件都不落。用户希望会话**跟随项目**留存并能续传。
- **模型配置各配各的**：本项目「模型」（`~/.ide/model-config.json`）与 pi 的凭证（`~/.pi/agent/auth.json` + `~/.pi/agent/models.json`）互不相识（`model-config.ts:6` 写明「这里不碰」）。用户在阅读器里配好一个 provider，pi 会话仍然用不了 —— 得去 pi 里再配一遍。

## 六、明确不做

- **OpenHands 的安装 / 会话 / 模型同步** —— 适配器还没接（仍只给指引）
- 会话的**跨机器漫游 / 云端同步**（记录只在本机 `~/.ide` 下）
- 会话记录里保存 pi 的**原始 jsonl 引用之外的副本**（pi 的消息不做二次落盘，避免两份真相）
- 模型同步的**反向流程**（pi → 本项目）与「以 pi 为准」的冲突合并
- 把同步过的模型设为 pi 的**默认模型**（改 `settings.json.defaultModel` 会替用户改 pi 的全局偏好；要用在 pi 里 `/model` 选）
- 会话记录的**自动清理 / 保留期策略**（先只做手动删）

### 实测踩到的坑（已修）

- **同一会话的写盘会交错**：内置 agent 一条消息触发一次写盘（user / assistant 各一次），并发 `writeSession` 出现「后一次写的内容先落、前一次的反而最后落地」→ 记录里只剩 1 条消息（A6 实测复现）。修法：`persistChain` 把同一会话的写盘排队，链尾永远 resolve。
- **内置 agent 的助手消息入历史晚于 `message_end`**（`runLoop` 先 emit 再 push）→ 只按 `message_end` 落盘会漏最后一条。修法：`agent_settled` 时再落一次。
- **UI 验收时序**：`AgentSessions.init()` 末尾的 `select()` 会清掉期间产生的错误 —— 脚本抢在它前面点「新建会话」时，刚出现的横幅会被抹掉（表现为「横幅不见了」）。断言前要先等 `GET /api/agent/sessions` 回来。
- **终端很窄时长命令会折行**：逐行断言会误判，得把文本压平再比。
- **活动栏与主区只做了单向联动**（用户实测报回）：`onSelectView` 原来只在「切到 code 会话」时把主区切成会话内容，切到**其它**面板（文件 / 搜索…）时不管 —— 于是从会话点「文件管理」，主区还停在会话内容。修法：`else if (mainView === 'agent') backToCode()`（只在当前确实停在会话时才回，不碰用户手动开的项目地图）。
