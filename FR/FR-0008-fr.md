# FR-0008 · 编辑器直接编辑 + 文件树删除（局部可写）

> 02/03 把「只读」写成了差异化定位（`docs/02-lens.md:222`、`docs/03-navigator.md:219`）。
> 本轮按用户要求打开一个**口子**：读代码时顺手能改一处、删一个临时文件，不用切去别的编辑器。
> 一句话：**打开即可编辑，停手 1s 自动落盘；文件树右键能删（进系统回收站）；不新增任何编辑辅助。**

## 一、为什么做（用户视角）

用户原话：「文件支持 删除，和编辑，但是不用提示词和任何辅助功能。解决一些零时问题，有修改后，1s 内自动保存。」

现状：

- 编辑器**写死只读**：`frontend/src/Editor.tsx:243`（`readOnly: true` + `domReadOnly: true`），内容由 `store.fileContent` 单向下发。
- 后端**只有读**：`GET /api/projects/:id/file`（`backend/src/api/routes.ts:648`）；写能力只有 git 提交类（`/git-write`）。
- 文件树右键菜单已有入口（`FileTree.tsx:41` 的 `LeafMenu`），但没有「删除」。

场景是「零时问题」：改一行配置、删一个误生成的文件、修个错别字——现在必须离开阅读器。不是要做 IDE 级的编写体验。

## 六、明确不做

- 新建 / 重命名 / 移动文件、目录操作（D4）
- 编辑器辅助：补全、诊断波浪线、格式化、快速修复、AI 提示词（用户明确「不用提示词和任何辅助功能」）

### 与本文的偏差

1. §四 漏列两处，实施时补上：`backend/src/indexer/store.ts`（`onFileDeleted` 必须收敛子树）与 `frontend/src/api.ts`（`ApiRequestError`）。
2. 冲突弹窗除「保留我的 / 用磁盘上的」外，Esc 或点遮罩 = **「稍后再说」**（本地改动留着，不丢）。用户只拍板了前两条，这条按「不丢用户改动」补。
3. `frontend/src/state.ts` 多一层 `lastWrites`（按 mtime 认领自己写的正文）：不加的话，「保存 → 立刻重开同一文件」会拿到索引缓存里的旧正文，再一改一存就把上一次修改盖掉。这是 `GET /file` 走索引缓存 + watcher 防抖窗口共同造成的，实测才发现。
4. 删除路由在自己删完后**主动**调一次索引收敛（`onFileDeleted`）：`watcher.ts` 只订阅 `unlink` / `change` / `add`，chokidar 的目录删除事件收不到，光靠 watcher 会留幽灵目录。
