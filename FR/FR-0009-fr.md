# FR-0009 · 文件基本能力（新建 / 重命名 / 移动 / 复制）

> FR-0008 打开了「改已有文件 + 删」的口子，并明确把 D4「不新建、不重命名、不移动」留到后面。
> 本轮就是关掉 D4：**文件树能新建文件、新建文件夹、重命名、移动、复制副本、剪切粘贴、拖拽移动**。
> 一句话：读代码时顺手补一个文件、改个错名、把文件挪进正确的目录，不用切去别的编辑器。

## 一、为什么做（用户视角）

用户原话：「增加新建文件的能力，新建目录的能力。rename 等文件的基本能力」。

现状（FR-0008 之后）：

- 后端写操作层 `backend/src/indexer/fswrite.ts` 只有 `writeProjectFile`（**只写已存在文件**）与 `trashEntry`（回收站删除）。
- 路由 `PUT /api/projects/:id/file`（改）、`DELETE /api/projects/:id/file`（删）——没有「建 / 改名 / 移 / 拷」。
- 文件树右键菜单只有：复制路径、复制文件名、在旁边打开、删除（`frontend/src/FileTree.tsx:341-387`）。
- 项目根在树里**不是一行**（`FileTree` 渲染 `tree.children`），所以必须给树容器加空白处右键菜单，否则根目录下新建无从下手。

### 与本文的偏差

1. §四 漏列两处，实施时补上：
   - `backend/src/api/routes.ts` 的 `normalizeEntryPath` 必须**单独**报 `path_escape`：原计划交给 `resolveInside` 兜，但 `..` 会先被规范化滤掉，实测退化成 `bad_request`（语义不对）。
   - `frontend/src/state.ts` 的 `localMoves` 窗口（见下条）。
2. **实测发现的真缺陷（已修）**：后端写完后 `verify()` 对账，会把被改名的**旧路径**当删除推一条 `file-deleted`；这条 SSE 消息是异步到的，往往落在 `openFileAt(新路径)` **之后**，于是刚跟随重开的编辑器又被「文件被删了」清空 —— 真机表现就是「重命名打开中的文件后编辑器一片空白」。（FR-0008 的 `localDeletes` 只覆盖删除，没覆盖「改名导致的删除」。）
3. 新增一个错误码 `same_path`：复制到自身原会落到 `into_self`，文案说成「不能移进自己的子目录」不对；现在 400 `same_path` → 前端「源和目标相同」。
4. 拖拽落点的实现取舍：`dragSource` 放 ref（hover 时读，不必重渲）、只有高亮的 `dropTarget` 进 state；落到**同一目录**直接不发请求（避免白跑一次必然 409 的往返）。
5. 树容器在「空树 / 被过滤空」时**也要渲染**（原来直接 return 一行空态 `div`）：否则空项目里没有空白处可右键，也就没法新建第一个文件。

### 未决（后续）

- 「移动到…」目前是**输入目标目录**（+ 拖拽 / 剪切粘贴两条快捷路径），没有目录选择树弹窗。
- 剪贴板是前端内存态，不接系统剪贴板、不跨项目、不支持多选。
- 不做覆盖（Q3）：目标已存在一律拒绝，用户自己改名或先删。
- 目录改名撞上句柄占用只如实报错（Q6），没有「新建目标目录 + 逐条搬移」的自动回退。
- 非 `git` 跟踪的改名不会顺带更新 git 索引（改名后 git 会显示 delete + add，用户自行 `git add -A`）。
