# FR-0015 · Code Agent 刷新后仍在 Agent 里 + 去掉「回到代码」按钮

> 用户原话（2026-10-21）：
> **「刷新进去 code agent 的时候展示的是代码。这个是不对的。另外将返回代码功能去掉，code agent 就是 code agent 不要代码视图，反正一样」**
>
> 一句话：Agent 模式要能**活过刷新**（进来时在哪，刷新后还在哪）；同时**不再提供「回到代码」按钮** ——
> Agent 就是 Agent，想回代码就点左栏别的视图，和以前点按钮是同一件事。

## 一、为什么做（用户视角）

- **刷新掉回代码视图**：`mainView` 是纯内存状态，只在「点活动栏 / 点会话」时被设为 `'agent'`；
  而它**不进 URL**（`writeSnapshot` 只写 `view=map`），所以刷新后初始化成 `'auto'` ——
  主区显示代码（或项目地图），左栏却还停在「code 会话」，两边不一致。
- **「回到代码」是多余的按钮**：它做的事和「点左栏任一其它视图」完全一样（`backToCode()`），
  而 Agent 模式里本来就没有代码视图可看 —— 留一个退回按钮，等于给一个不存在的分支留出口。

## 二、已拍板（用户原话直接定）

| # | 结论 | 落地含义 |
|---|---|---|
| 1 | 刷新后仍在 Agent 里 | `mainView` 初值改为**按活动栏存档认领**：某侧选中的视图是 `agent` → 进来就是 Agent |
| 2 | 去掉「返回代码」 | 删掉中间会话头（`AgentView`）与左栏会话头（`AgentSessions`）上的两个按钮，连带 3 条 i18n key |
| 3 | 「不要代码视图」 | 不改动渲染分支（Agent 模式本来就只画会话）；只是不再提供「显式退回」入口 |
| 4 | 退出路径不变 | `onSelectView` 的既有联动：在 Agent 模式里点左栏其它视图 → 主区 `backToCode()` |

## 三、实现（穷尽）

| 文件 | 改动 |
|---|---|
| `frontend/src/App.tsx` | `mainView` 初值：`layout.active.left / right === 'agent'` → `'agent'`（**带 `?file=` 深链时例外**：那是明确要看某个文件，仍进代码视图）；删除 `<AgentSessions onBack={backToCode}>` 与 `<AgentView onBack={backToCode}>` 两处传参。`backToCode()` 本身保留 —— 打开文件 / 继续阅读 / 「会话→其它面板」联动都还靠它 |
| `frontend/src/AgentView.tsx` | 删 `onBack` prop 与头部「回到代码」按钮 |
| `frontend/src/AgentSessions.tsx` | 删 `onBack` prop 与 `.ag-side-head` 里的「回到代码」按钮（标题 `Code Agent` 保留） |
| `frontend/src/i18n/zh.ts` / `en.ts` | 删 `app.backToCode`、`agent.backToReadingTitle`、`agent.backToReadingHint`（仅这三处引用） |
| `docs/10-features.md` / `.en.md` | Code Agent 一节：「点『回到代码』即切回」→「点左栏任一其它视图即切回；刷新后仍停在 Agent 模式」 |

设计取舍：

- **不把 `mainView` 写进 localStorage / URL**：活动栏的选中视图（`wcr:layout`）本来就已经持久化，
  再存一份主区视图就是两个真相源，必然对不上。按它推导最省事，也不会出现「左栏 agent、主区代码」的错配。
- **深链 `?file=` 优先**：贴出去的「看这个文件」链接不该被上次遗留的 Agent 模式抢走。
- **`backToCode()` 留在内部**：它不是「返回按钮」的实现，而是「主区回代码视图」这一动作；
  `jump()`（打开文件）、`continueReading`（继续阅读）、`onSelectView` 三处都要它。

## 五、明确不做

- 不把 Agent 模式塞进 URL 快照（`view=agent`）—— 会与「活动栏选中视图」重复表达同一件事
- 不新增「关掉 Agent」菜单项 / 快捷键（点活动栏即退出）
- 不动 Agent 模式下右栏自动切终端、底部面板收拢这些既有行为

## 六、结果（2026-10-21 实施）

- `App.tsx`：`mainView` 初值按 `layout.active` 认领（含 `?file=` 例外）；两处 `onBack` 传参删除。
- `AgentView.tsx` / `AgentSessions.tsx`：删按钮与 `onBack` prop；i18n 三 key 删除；中英文档同步。

### 踩到的坑

- **`mainView` 是纯内存状态**：只改 localStorage 存档的读写并不能修好刷新问题 —— 判定依据必须落在
  已经持久化的那一份数据上（`wcr:layout` 的 `active`），否则又是两个真相源。
- **深链 `?file=` 会被 Agent 模式抢走**：第一版只看 `layout.active`，带文件深链打开也进 Agent；
  真机脚本 A5 覆盖后加上了例外判断。
- **`npm run build` 会被工作区里别人的半成品挡住**：`build` = `tsc --noEmit && vite build`，
  而 `FileTree.tsx` 当时还缺 `onRevealInExplorer` 的声明。真机验收期间改用 `npx vite build`
  单独出产物（产物一致）；等那边补完后 `npm run typecheck` 前端已通过。
