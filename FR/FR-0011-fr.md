# FR-0011 · 在终端中运行（Run in Terminal）

> 阅读代码时想就地跑一下：文件树点右键、编辑器点一下，就在**已有的那个终端**里执行当前文件，
> 不用手敲整条命令、也不用切到别的编辑器。等价 VS Code 的「Run Active File In Active Terminal」，
> 但按语言推断出真正的命令（`python foo.py`、`node a.js`），并且能选 Python 环境。
> **不做 debug**（不接 DAP、不出调试图标、不配 launch.json）。

## 一、为什么做（用户视角）

用户原话：「openvscode-server 这里有 vscode 实现源代码，我想借用他的 code run 能力，
我不做 debug，但是我想让他有 run in terminal 这种」。

摸底结论（先纠正一个预期）：

- VS Code / openvscode-server **没有**「按语言跑当前文件」的内置能力（那是第三方 Code Runner 扩展）。
  它内置的只有两条命令，都在 `src/vs/workbench/contrib/terminal/browser/terminalActions.ts`：
  - `Run Selected Text In Active Terminal`（L564）→ 选区文本（空选区取当前行 `.trim()`）送进激活终端；
  - `Run Active File In Active Terminal`（L587）→ **只把文件路径**送进激活终端。
- 真正值得借的是两个底层件：
  - `preparePathForShell()`（`common/terminalEnvironment.ts:320`）—— 路径按 shell 转义的规则表
    （PowerShell 有空格/括号/单引号 → `& 'path'`；Git Bash → 反斜杠转正斜杠 + 单引号；cmd 有空格 → `"path"`）；
  - `sendText()`（`browser/terminalInstance.ts:1343`）—— 换行归一成 `\r`、要执行时末尾补 `\r`、
    终端开了 bracketed paste 就包 `\x1b[200~…\x1b[201~`（防止多行文本被逐行执行）。

本项目侧现状（已核对）：

- 终端 = 前端 `frontend/src/TerminalPanel.tsx`（xterm + 多标签 + 分屏，pane 的 `term`/`ws` 是组件内私有状态）
  + 后端 `backend/src/api/terminal.ts`（node-pty + 自研 WebSocket 帧）。
- 协议里**已经有** `{type:'input', data}`（TerminalPanel.tsx:194-198）→ **"把命令送进终端执行"这条链路天然存在，
  后端 terminal.ts 一行都不用改**；工作量全在前端 + 一个 Python 环境探测接口。
- 文件树右键菜单已有基础设施（`FileTree.tsx` 的 `menu` 弹层 + `onXxx` 回调到 App）。
- 编辑器用 `editor.addAction()` 注册右键项（`Editor.tsx:339` 起），回调走 `onXxxRef.current`。
- 编辑器标签栏在 `App.tsx` 的 `.editor-topbar`（标签条 + 右侧 `.editor-actions` 的 ←/→/分享），▶ 按钮放这里。

| # | 问题 | 选择 | 落地含义 |

| 2 | 触发入口 | **全要**：文件树右键、编辑器右键、编辑器标签栏 ▶ 按钮、快捷键 | 四处调用同一个动作 |

## 三、默认（我的判断，不同意就直说）

| # | 未拍板项 | 默认做法 |
|---|---|---|
| D1 | 「命令面板」这个入口 | **本仓库没有 VS Code 式命令面板**（Ctrl+Shift+P 不存在；现有 `CommandPanel.tsx` 是"当前项目命令 + 后台任务"面板，语义不搭）。所以只做 **Ctrl+F5** 全局快捷键（等价价值），不做命令面板条目；要真命令面板另立 FR |
| D2 | 语言 → 命令表 | 只收"单文件可直接解释执行"的：`.py/.pyw`→`<python>`、`.js/.mjs/.cjs`→`node`、`.go`→`go run`、`.ps1`→`pwsh -File`（无 pwsh 用 `powershell -File`）、`.sh/.bash`→`bash`、`.rb`→`ruby`、`.php`→`php`、`.pl`→`perl`、`.lua`→`lua`、`.bat/.cmd`→`cmd /c`。表是一张 `Record<string, string[]>`，加语言只加一行 |
| D3 | 路径转义 | 照搬 `preparePathForShell` 规则，按当前 pane 的 shellKind 分支（PowerShell → `& '…'` / Git Bash → `/` + `'…'`）。**不用** bracketed paste（我们送的是单行命令） |
| D4 | 「哪个文件」 | 文件树右键 = 那个文件；编辑器右键 / ▶ 按钮 / Ctrl+F5 = 当前打开文件（`store.openFile`） |
| D5 | 多标签 / 分屏 | 写到**激活标签的第一个 pane**（本仓库只有标签级激活，没有 pane 级激活） |
| D6 | 终端未打开 | 展开底部面板 → 切到「终端」标签 → 新建一个标签 → 等 shell ready 再写入 |
| D7 | shell 未 ready 时写入 | 后端 `handleClientMessage` 在 `spawn` 之前会丢 `input`（`if (!session.pty) return`）。所以 TerminalPanel 要缓存 pending 命令，收到 `title`（spawn 成功）后再 flush |
| D8 | Ctrl+F5 键位 | 两套 keymap 都绑 `Ctrl+F5`（VS Code 里 F5/F5 系是调试键，但我们不做 debug，无冲突） |
| D9 | Python 探测位置 | 只看**项目根**：`.venv`/`venv`/`env` 下 `Scripts\python.exe`（Win）/ `bin/python`（POSIX）；有 `conda-meta` 则用 `python`（交给已激活的 conda 环境）。找不到 → 用 PATH 上的 `python` |
| D10 | 设置项形态 | `prefs` 加 `pythonPath: string`（空 = 自动探测），走既有的版本迁移机制（`PREFS_VERSION` v1→v2），设置面板给一个输入框（选完**非空就完全覆盖**探测结果） |
| D11 | 解释器/运行器不在 | 命令照写（终端会报 `command not found`）——不预检 PATH，保持"所见即所得"（用户能立刻看到真实报错） |
| D12 | 共享模式 | 终端在共享模式下整层不可用（`terminal.ts:161`），运行入口同样禁用（按钮/菜单置灰并提示） |
| D13 | 运行前的可见性 | 不额外清屏、不插入注释；命令由 xterm 回显，用户可 Ctrl+C 打断 |
| D14 | 命令里的解释器路径 | 探测到的解释器用**绝对路径且加引号**（`& 'D:\p\.venv\Scripts\python.exe' 'src\a.py'`），让"用了哪个环境"在终端里一眼可见；PATH 兜底时写裸 `python` |
| D15 | 相对路径 | 文件在项目内 → 项目相对路径；文件在项目外（理论上不会有）→ 绝对路径 |

## 六、明确不做

- **debug**：不接 DAP、不出调试图标、不读 `launch.json` / `tasks.json`
- **选区运行**（Run Selected Text）——用户明确不要
- 编译器型语言（`.ts`/`.java`/`.c`/`.cpp`/`.cs`/`.rs`/`.kt`）——需要构建步骤，不是"run in terminal"该干的事
- 通用命令面板（Ctrl+Shift+P）——要的话另立 FR
- 完整环境管理器（nvm/pyenv/conda 多环境切换 UI）——本轮只做"项目 venv 探测 + 手填一个路径"
- 输出回收到「输出」面板（就是在终端里跑，结果留在终端）
- `cd` 到文件所在目录 —— 与 D7 口径一致，终端始终停在项目根
- 运行历史 / 每文件的"最近运行命令"（要的话后续加）

### 与本文的偏差

1. 引号口径比 VS Code 更保守：探测 / 手填的解释器**一律加引号**（VS Code 只在有空格时才加）——
   `D:\proj\.venv\…` 的盘符冒号在 PowerShell 下裸写易踩转义坑。
2. 「标签栏 ▶ 按钮」落在编辑器顶条右侧的 `.editor-actions`（`←` `→` 之前），不是"标签上"。
3. Python 探测接口路径钉为 `GET /api/projects/:id/python`（本文只写了"新接口"）。
4. A3 的"中文路径"未单独造用例（空格 / 括号 / 单引号已覆盖，中文与空格同类）。
5. **并发背景**：本仓库同期有另一会话在改同一批文件（终端 shell 选择器 `PowerShell/Git Bash`、
   终端「常驻不卸载」、conpty.dll）；本次改动基于其工作区状态**增量叠加**，未触碰其内容。
   也因此真机 UI 需要**先 `npm run build`**（后端服务的是 `frontend/dist`），否则验的是旧产物。
